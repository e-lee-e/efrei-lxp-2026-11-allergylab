## 2. Les défauts trouvés et corrigés

Chacun a un symptôme chiffré. Aucun n'était visible sur un score global.

| Défaut | Symptôme mesuré | Correctif |

## 5. Pour la personne qui configure l'agent

Les commandes sont dans l'ordre. Chaque étape a son critère de réussite ; si un
critère n'est pas atteint, s'arrêter là, ne pas lancer de question.

### 5.1. Installer

    uv sync
    uv sync --extra bureau

Critère : `uv run kit controle --hors-ligne` affiche RÉUSSITE. S'il manque
`gi` pour la fenêtre : `uv pip install --python .venv/bin/python pygobject`.

### 5.2. Poser la clé

    uv run kit cle

La clé se saisit sans écho et part dans `~/.allergylab/cle` en 600. Elle ne se
colle jamais dans un fichier du dépôt, ni dans un terminal journalisé, ni dans un
chat.

Critère : `uv run kit controle` (sans `--hors-ligne`) affiche la ligne
« appel au modèle : … a répondu (N jetons) ». C'est la seule vérification de la
clé qui n'affiche jamais sa valeur.

### 5.3. Vérifier avant de travailler

    uv run kit controle --hors-ligne
    uv run pytest equipe/tests -q

Critère : RÉUSSITE et 147 tests passés. Ces deux commandes coûtent 0 $ et
attrapent tout ce qui casse en arrivant, y compris une fusion ratée.

### 5.4. Choisir le modèle

Haiku 5.5 est le modèle de développement, et le seul autorisé. Le sélecteur de la
fenêtre ne vaut que pour le processus en cours ; un `uv run kit agent` repart sur
Haiku même si la fenêtre affiche autre chose. Aucun choix de modèle ne se commite.

`--modele officiel` (Sonnet) coûte 20 fois plus et n'est pas autorisé aujourd'hui.

### 5.5. Lancer

    uv run kit agent "Combien de patients ont moins de 18 ans ?"
    uv run --extra bureau python -m equipe.bureau

La question de référence doit répondre 2 272 sans appel au modèle, donc 0 $. La fenêtre
s'appelle DatAllerGy ; après un `git pull`, il faut la relancer, sinon elle
continue d'exécuter l'ancien code.

### 5.6. Mesurer

La batterie versionnée ne porte que les questions, jamais les réponses. Pour
noter, il faut un corrigé calculé sur la machine, hors dépôt :

    uv run kit evaluer ~/.allergylab/benchmark/batterie-complete.toml
    uv run kit bilan

Critère : justesse 26/26, abstentions 30/30, environ 0,03 $ la passe. La recette
du corrigé (calcul en pandas, tolérance sur les questions ambiguës) est dans la
référence `mesure-et-corrige` de la compétence du projet.

### 5.7. Les plafonds à connaître

| Réglage | Valeur | Variable |
|---|---|---|
| étapes par question | 5 | `ALLERGYLAB_ETAPES_MAX` |
| jetons de sortie par appel | 2 000 | `ALLERGYLAB_SORTIE_MAX` |
| délai par question | 35 s | `ALLERGYLAB_DELAI_MAX` |
| cache | actif | `ALLERGYLAB_SANS_CACHE=1` pour le couper |

Sans `ALLERGYLAB_SANS_CACHE=1`, une question déjà posée sort à 0 jeton et ne
mesure rien.

### 5.8. Ce qui se passe si ça se passe mal

La fenêtre ne laisse jamais l'utilisateur sans issue : clé manquante, fichier
illisible, délai dépassé et panne ont chacun leur bouton. Une question qui échoue
reste dans la barre de saisie.

Si un fichier ne se lit pas, le précédent reste actif : rien n'est perdu. Si une
question rend une abstention, ce n'est pas une panne : c'est que le fichier ne
contient pas la réponse, et la justification dit pourquoi.

## 6. Les limites à connaître, écrites noir sur blanc

- Une question ambiguë est tranchée par le système. Sur deux questions de la
  batterie, exclure ou garder les patients non renseignés est également
  défendable ; la note porte une tolérance au lieu de trancher.
- Un fichier étranger qui porterait nos noms de colonnes avec un autre codage —
  un `Gender` où 0 voudrait dire homme — serait lu avec notre codebook et
  répondrait faux. Rien dans le fichier ne permet de le détecter.
- Les réglages ne sont validés que sur Haiku. Si la passe officielle tourne sur
  Sonnet, rien de ce document ne garantit le comportement : un échantillon de six
  questions n'avait pas cassé le contrat, mais c'était avant les corrections.
- Le cumul de `kit bilan` est un plancher. Un appel interrompu peut être facturé
  sans laisser de trace.

Passée le soir, sans cache, sur le code corrigé.

| Terrain | Résultat | Coût par question | Temps |
|---|---|---|---|
| Batterie de référence, 56 questions | justesse **26/26**, abstentions **30/30** | 0,000457 $ | 1,9 s |

Les quatre jeux sont le jumeau synthétique (5 000 × 256), l'immunothérapie en
Excel (90 × 8), la dermatologie sans en-tête (366 × 36) et NHANES 2005-2006 en SAS
(9 440 × 106, allergies déclarées et IgE spécifiques). Les dix questions portent
sur des comptages et un âge médian, avec la vérité calculée à côté en pandas :
neuf tombent juste, et l'abstention est celle qu'on sait expliquer.

Ce qu'on peut dire le 18 au soir :

- **le fichier du kit est couvert** : aucune erreur connue sur les 73 questions
  notables des deux batteries ;
- **un fichier étranger ne casse plus rien** : il se lit, ou il le dit, et deux
  fichiers ne partagent jamais une réponse ;
- **une erreur offre toujours une sortie** dans la fenêtre, et la question reste
  dans la barre.

Ce qui reste ouvert, et qui ne se ferme pas en une soirée :

- une question posée en français sur une table dont les colonnes sont en anglais
  s'abstient au lieu de traduire (« arachide » contre une colonne `peanut`) ;
- la taxonomie molécule vers famille n'existe pas, donc les questions de famille
  d'allergènes s'abstiennent ;
- un fichier qui porterait nos noms de colonnes avec un autre codage serait lu
  avec notre codebook, et répondrait faux sans le dire.
